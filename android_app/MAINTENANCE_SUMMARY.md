# 一链取影 Android APP 维护总结

更新时间：2026-11-07

## 1. 项目定位

“一链取影”Android 客户端使用 Flutter 开发，服务地址由 `lib/services/api_service.dart` 统一管理。GitHub 仓库只保存 Android APP 源码和 APK 自动构建流程。

## 2. 当前主要功能

- 识别用户粘贴的分享链接并展示视频或图集结果。
- 从手机相册选择本地视频并进行本地预览，不扣每日提取次数。
- 视频、图集保存到手机相册。
- 记录页支持复制下载链接和再次保存到相册。
- 图片局部修复，支持矩形框选和画笔标记。
- 每日免费额度为 10 次，并显示稳定的设备专属 ID。
- 支持卡密兑换次数或不限次服务。
- 支持意见反馈、清空手机本地历史记录。

## 3. 隐私与合规

- 首次打开 APP 显示版权提示，用户同意后才能继续使用相关功能。
- “我的”页面提供《用户协议》和《隐私政策》入口。
- 仅在用户主动操作时读取剪贴板、选择本地素材或保存到相册。
- 不要求手机号、头像、昵称、通讯录或地理位置。
- 图片修复等云端任务会上传用户主动选择的素材；临时素材最多保存 24 小时。
- 视频号链接可能发送给腾讯元宝完成处理。
- 不得处理未获授权的第三方素材，不得擅自删除他人作品的水印、作者标识或权利管理信息。
- 权利投诉与隐私联系邮箱：`sd0739@sd0739.top`。

## 4. 下载与相册保存修复

- 下载进度弹窗只关闭自身，避免重复执行页面导航导致黑屏。
- 用户取消下载后不会再次关闭当前页面。
- 本地视频和网络视频使用不同的保存流程。
- 记录页的视频和图集均可重新保存到相册。

- `.github/`

## 6. APK 自动构建

推送到 `main` 分支后，`.github/workflows/build_apk.yml` 自动执行：

1. 配置 Java 与 Flutter。
2. 重建标准 Android 工程。
3. 安装依赖并构建 Release APK。
4. 上传 `yitie-quying-release-apk` 构建产物。

GitHub Actions 的 ZIP 解压后可得到 `app-release.apk`。

## 7. 发布前检查

1. 确认桌面名称显示为“一链取影”。
2. 确认首次版权提示、《用户协议》和《隐私政策》可以打开。
3. 确认每日免费额度显示 10 次，专属 ID 可复制。
4. 测试链接提取、本地视频选择、卡密兑换和意见反馈。
5. 分别测试网络视频、本地视频和图集保存到相册。
6. 测试下载完成及取消后不会出现黑屏。
7. 检查仓库中没有密码、Cookie、Token、SMTP 授权码、私钥或数据库。

## 8. 安全规则

- 运行密码和密钥只能通过服务器环境变量或受限配置文件设置。
- 不得把真实 Cookie、卡密、后台密码或邮件授权码写入代码和文档。
- 不得提交 APK、ZIP、数据库、缓存或用户素材。
- 修改功能后必须通过 GitHub Actions 构建成功再交付安装包。

## 9. 账号找回与卸载重装自动恢复（2026-11-07）

- 当前版本：`1.0.3+4`，发布文件 `yilian-quying-v1.0.3.apk`；
- 用户 ID 旁和功能菜单提供“找回/切换”，支持老用户 ID、已使用卡密和恢复码；
- 恢复码生成后自动复制，并提供“一键复制”按钮；
- `StorageService.getUserId()` 使用 `android_id 0.5.2` 取得应用专属匿名设备标识；
- `ApiService.authenticateAndroid()` 调用 `POST /api/auth/android`，首次升级继承当前本地账号，以后同一签名 APK 重装自动恢复；
- 服务器只保存 HMAC 摘要，不保存明文设备标识；隐私政策已披露该用途；
- 自动恢复不替代恢复码：恢复出厂、系统用户变化或 APK 签名变化时，仍需恢复码/旧 ID/已使用卡密。

构建记录：功能提交 `85c0ef1` 首次因 Dart 可空类型失败；修复提交 `02a46ba` 将返回值明确为非空。正式发布必须配置固定 release keystore，否则不同构建的签名可能变化，影响覆盖安装及设备身份连续性。
